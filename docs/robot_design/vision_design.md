## 1.视觉功能描述与定位
### 1.1 功能描述

视觉设计主要用途实现二号机器人（叉车＋滑轨）的半自动化：操作手按下按钮，二号机器人可以自动升降车叉，摄像头感应对齐后发送停止指令，实现二号机器人**半自动化**，以精准抓取高台黄色方块。

### 1.2 功能定位

**第一步：从实际要求总结视觉目标**

比赛场地的关键地形包括：
- 外部立方体规格： 30mm*30mm*30mm 
- 内部镂空立方体规格： 15mm*15mm*15mm 
- 四个位于距离中心 40mm，10mm 高的十字形基座上
- 高 70mm的高台上一个

这意味着：
1. 方块很小，不便于操作手观察；
2. 中心方块需要精确抓取；
3. 地形对精确度要求高。

**第二步：视觉运用的要求**

通过安放在车叉上、跟随车叉运动的摄像头，根据方块黄色边框计算中心位置；计算由主机进行，主机向stm32发送明确的布尔信息实现半自动，同时不会因为数据过于复杂而丢失。

**第三步：视觉运用的定位**

视觉作为二号机器人的专门功能，为配合二号车主要抓取中央区域方块、次要抓取物资架上方块的特点，具有以下定位：

- 半自动辅助，是二号机器人实现其功能的重要组成 
- 对黄色方块专精：仅实现对黄色方块的的识别即可

## 2. 视觉算法选型
### 2.1 功能描述

视觉算法要求能精准找到黄色方块的中心，并在对齐时将数据发给stm32


### 2.2 开发历程

**第一版方案**

一开始我们拟采用灰度化+大津法（Otsu）进行阈值分割。但在对照比赛手册第15、16页场地材质后，发现致命缺陷：**场地高台为木色，能量单元为白色，与目标黄色方块在灰度图下极易混淆**；且赛场**灯光不可控**，全局阈值容易失效。

**第二版方案** 

团队决定转入 HSV 色彩空间。通过锁定 H（色相）为黄色，结合 S（饱和度）过滤白色方块，从根本上解决光照干扰与背景融合问题。同时引入几何特征校验（面积、宽高比），过滤高台边缘的干扰。

**具体实现**
通过高斯滤波 -> HSV转换 -> inRange -> 形态学开闭运算 -> findContours -> 计算中心点，抓取到足够面积的黄色方框，并计算其中心区域；位于区域时，发送停止指令。

**注意**
- 考虑到延迟和惯性，应通过调试确定中心区域大概面积
- 调试阶段，发送位置相对偏离信息；调试完成后，仅发送布尔信息

## 3. 视觉与电控系统协议

### 3.1 硬件准备
- 香橙派 Zero 3 
- STM32
- 免驱usb摄像头

### 3.2 调试阶段协议
在前期联调阶段，主要帮助操作手判断距离。视觉系统通过计算目标方块的像素面积（或垂直方向的中心差值），输出三种状态：
*   `0x01`：目标偏高/偏小（离得远）
*   `0x02`：目标偏低/偏大（离得近）
*   `0x03`：识别到目标
*   `0x00`：未识别到目标
调试阶段，进行静态与动态识别，此时不考虑与电控协调问题

### 3.3 比赛阶段协议（触发确认模式）
完成调试后，视觉系统仅作为“精准对齐的触发器”，只发送是否瞄准成功的布尔指令：
*   `0x01`：**已找到并对齐**（目标中心落入十字准星阈值内），STM32收到后触发叉车升降机构进行抓取。
*   `0x00`：未对齐或未找到，电控不执行自动抓取。

### 3.4 串口帧结构定义
为防止串口通信中常见的断帧、错帧现象，采用4字节定长帧结构：

| 字节序号   | 含义   | 说明                             |
| :----- | :--- | :----------------------------- |
| Byte 0 | 帧头   | `0xAA`                         |
| Byte 1 | 状态指令 | `0x00`, `0x01`, `0x02`， `0x03` |
| Byte 2 | 校验和  | 前2个字节的异或和                      |
| Byte 3 | 帧尾   | `0x55`                         |

## 4.调试与异常处理

### 4.1 静态调试
手动抬升方块，静止在不同位置，判断摄像头是否能正确识别，并不断调试参数。

### 4.2 动态调试
摄像头与车叉联动好后，车叉自动抬升方块，判断摄像头是否能正确发送车叉停止指令、车叉停放位置是否正确。调整车叉速度和识别参数。
### 4.3 动态阈值调优
在代码中封装滑动条（Trackbar）调试接口，赛前检录及调试环节，允许操作手在场地上根据真实灯光动态调整 HSV 阈值，并保存至配置文件。
### 4.4 异常与丢帧保护 
如果在运动过程中，由于机械震动导致画面模糊或目标突然丢失，视觉系统连续发送 3 帧 `0x00`（未识别/未对齐）。若 STM32 收到连续 3 帧 `0x00`，则立即切断叉车电机的自动抬升指令，防止机械结构因盲目运行而卡死或损坏。

## 5. 硬件安装与部署
> - **视觉主控**：香橙派 Zero 3（负责运行 OpenCV 算法并解算中心点）。
> - **图像输入**：免驱 USB 摄像头，固定在叉车升降滑轨前端。
> - **安装角度**：摄像头镜头呈水平或微向下 15° 俯角，确保在叉车抬升过程中，黄色方块始终处于画面中心区域。
> - **通信接口**：香橙派 UART 串口与 STM32 交叉连接（TX-RX, RX-TX），共地。
