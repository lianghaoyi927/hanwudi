# 机器人电控系统与遥控通信开发1.0

## 1. 功能概述
本模块实现了机器人的核心电控系统，主要包括两部分：
1. **电机驱动模块**：实现对N20底盘电机与TT滚轮电机的PWM调速与正反转控制。
2. **PS2无线遥控模块**：实现操作员通过PS2手柄对机器人底盘进行实时运动控制，以及后续的拾取机构触发。
本阶段目标为打通硬件底层驱动与无线通信链路，完成软硬件联调。

## 2. 开发历程与遇到的技术难点（迭代优化过程）

### 阶段一：底层驱动独立测试（单点验证）
在拿到电机和驱动模块后，我们首先编写了基础的控制代码，并进行了独立测试。
*   **操作**：使用测试代码直接输出固定的PWM波形，观察电机运转状态。
*   **结果**：单独测试时，N20电机与TT马达均能正常正反转，TB6612驱动模块工作正常。这说明我们的底层引脚配置和电机驱动代码逻辑是基本正确的。

### 阶段二：PS2遥控通信的建立与配对（难点突破）
将PS2接收器接入STM32后，遇到了通信无法建立的问题。
*   **问题现象**：接收器通电后，指示灯一直处于闪烁状态，无法与手柄建立连接。
*   **排查与解决**：我们首先排查了供电问题，确保接收器VCC接3.3V且与主控共地。在确认供电无误后，发现接收器模块上带有一个隐藏的“配对/复位小孔”。使用工具戳按该复位孔后，接收器绿灯常亮，**成功完成强制配对**。
*   **代码优化**：原开源驱动代码中 `PS2_ReadData` 函数仅循环读取了6个字节，导致左摇杆的模拟值（位于第7、8字节）无法获取。我们将循环次数 `i < 6` 修改为 `i < 9`（并在头文件中同步修改了缓存数组大小），成功获取了完整的按键与摇杆数据。

### 阶段三：软硬件联调（当前遇到的问题）
在进行遥控器与电机的联合调试时，遇到了新的异常。
*   **问题现象**：手柄与接收器已配对成功，且之前单独测电机正常；但联调时，推动摇杆/按下按键，轮子不转。
*   **排查思路（进行中）**：
    1. 检查是否发生了**引脚冲突**（PS2占用了PB12~PB15，需确认电机定时器是否复用了这些引脚）。
    2. 检查**供电系统**。在调试中我们发现杜邦线无法承受大电流，甚至出现了**接上电源线直接烧毁（发热熔化）**的极端情况。这极大可能是因为供电线径太细、接线端子接触不良，或者电路存在瞬间短路。
    3. 下一步计划将动力电源（电池直接接TB6612的VM）与控制电源（降压模块给STM32供电）彻底隔离走线，加粗电源线，确保在电机启动瞬间主控芯片不会因为电压拉低而复位死机。

## 3. 技术选型与设计思路（为什么这样做）

*   **PS2遥控协议**：相比蓝牙或WiFi，PS2手柄的2.4G通信延迟极低，实时操控手感好，且抗干扰能力强，非常适合比赛现场复杂的电磁环境。
*   **PWM调速频率**：在CubeMX中，我们将定时器PWM频率配置为10kHz。这个频率既超出了人耳听觉范围（避免电机发出刺耳啸叫），又能保证电机在低速运转时有足够的平滑度。
*   **电机死区控制**：在电机换向代码中加入了1ms的死区延时，防止TB6612的H桥上下管同时导通导致短路烧毁。

## 4. 后续优化方向
1. 彻底解决电源供电烧线的问题，重新规划PCB或使用更粗的硅胶线连接大电流通路。
2. 完成摇杆模拟值到电机速度（-100~100）的线性映射，加入死区阈值防手抖漂移。
3. 实现麦克纳姆轮的全向移动解算（Vx, Vy, Vw）与遥控器的联动。

# 机器人底盘运动与供电系统迭代2.0

## 1. 功能概述
本阶段主要完成了机器人底盘运动控制的基础闭环。实现了从PS2手柄指令到电机底层驱动的完整链路，并对供电系统进行了重构。目前机器人已具备独立行走、前后移动及原地旋转的能力。

## 2. 开发历程与核心难点解决（迭代优化过程）

### 2.1 异常现象一：无指令下的“幽灵旋转”
*   **问题现象**：在初始调试时，未操作遥控器，部分轮子出现无指令自动旋转的现象。
*   **排查与解决**：经过排查，发现是PS2手柄摇杆的模拟值存在“中位漂移”（静止时并非精确停留在128）。我们在代码中加入了**“死区控制（Dead Zone）”**逻辑，当摇杆值在（例如110~145）之间时，强制将输出速度映射为0，成功解决了幽灵旋转问题。

### 2.2 异常现象二：单轮“偏科”与不均匀行走
*   **问题现象**：调试中发现一个轮子在向后和旋转时正常，但在直线前进时明显偏慢；后期又出现某单轮因物理差异转速过快，导致小车无法直线行走。
*   **原因分析**：N20减速电机为开环控制，内部齿轮摩擦力与线圈绕组的微小差异会导致相同PWM下转速不同。此外，初始阶段的单个轮子偏慢可能是接触阻力或控制逻辑中速度参数写反所致。
*   **解决方案**：在软件层面引入了**“权重补偿法”**。通过多次架空测试，观察四个轮子的实际转速，对偏慢或偏快的轮子赋予独立的系数（如 `speed * 1.15` 或 `speed * 0.85`），实现视觉上的转速同频，保证直行时的运动均匀性。

### 2.3 硬件重构：独立供电与线缆管理
*   **问题回顾**：前期调试因电机启动电流过大，出现过杜邦线发热甚至烧毁的险情。
*   **方案设计**：我们采用了**“动力与控制分离”**的设计思路。将电池动力线直接连接至TB6612的电机电源（VM）端，确保大电流通畅；同时，使用切开后的独立降压模块，将电池电压降至5V，专供STM32主控及PS2接收器使用。
*   **线缆规整**：引入面包板对控制信号线和供电线进行集中规整，减少飞线交叉造成的信号干扰与短路风险。

## 3. 技术选型与设计思路（为什么这样做）

*   **为什么采用独立降压模块？** 之前烧毁杜邦线的教训表明，主控板直接接动力电池极易因电压波动烧毁芯片。使用独立降压模块给控制器供电，能有效实现**电源隔离**，即使电机启动瞬间拉低整体电压，也不会导致STM32死机或重启。
*   **为什么引入死区控制？** 这是低端模拟摇杆的通用解决方案。如果不加死区，机器人会自己乱跑，严重影响调试效率和比赛表现。设置死区不仅能过滤手抖，还能掩盖部分摇杆硬件的老化问题。

## 4. 当前遗留问题与后续优化方向
目前底盘已实现前后直行和原地旋转，但尚未实现侧向平移。
1.  **麦轮解算优化**：当前代码大概率未完整实现麦克纳姆轮的X型全向解算。下一步计划将摇杆的左右Y轴数据正式引入横向速度（Vy），结合正向速度（Vx）和旋转（Vw），严格按照公式（LF=Vx+Vy+Vw 等）驱动四轮，实现真正的全向平移。
2.  **PID闭环控制（进阶）**：开环补偿虽然有效，但受电池电量衰减影响较大。若有时间，计划引入编码器，使用简单的速度环PID让车轮转速实现真正的自动化同步。
