# 机器人电控系统与遥控通信开发

## 1. 功能概述
本模块实现了机器人的核心电控系统，主要包括两部分：
1. **电机驱动模块**：实现对N20底盘电机与TT滚轮电机的PWM调速与正反转控制。
2. **PS2无线遥控模块**：实现操作员通过PS2手柄对机器人底盘进行实时运动控制，以及后续的拾取机构触发。
本阶段目标为打通硬件底层驱动与无线通信链路，完成软硬件联调。

## 2. 开发历程与遇到的技术难点（迭代优化过程）

### 阶段一：底层驱动独立测试（单点验证）
在拿到电机和驱动模块后，我们首先编写了基础的控制代码，并进行了独立测试。
*   **操作**：使用测试代码直接输出固定的PWM波形，观察电机运转状态。
*   **结果**：单独测试时，N20电机与TT马达均能正常正反转，TB6612驱动模块工作正常。这说明我们的底层引脚配置和电机驱动代码逻辑是基本正确的。

### 阶段二：PS2遥控通信的建立与配对（难点突破）
将PS2接收器接入STM32后，遇到了通信无法建立的问题。
*   **问题现象**：接收器通电后，指示灯一直处于闪烁状态，无法与手柄建立连接。
*   **排查与解决**：我们首先排查了供电问题，确保接收器VCC接3.3V且与主控共地。在确认供电无误后，发现接收器模块上带有一个隐藏的“配对/复位小孔”。使用工具戳按该复位孔后，接收器绿灯常亮，**成功完成强制配对**。
*   **代码优化**：原开源驱动代码中 `PS2_ReadData` 函数仅循环读取了6个字节，导致左摇杆的模拟值（位于第7、8字节）无法获取。我们将循环次数 `i < 6` 修改为 `i < 9`（并在头文件中同步修改了缓存数组大小），成功获取了完整的按键与摇杆数据。

### 阶段三：软硬件联调（当前遇到的问题）
在进行遥控器与电机的联合调试时，遇到了新的异常。
*   **问题现象**：手柄与接收器已配对成功，且之前单独测电机正常；但联调时，推动摇杆/按下按键，轮子不转。
*   **排查思路（进行中）**：
    1. 检查是否发生了**引脚冲突**（PS2占用了PB12~PB15，需确认电机定时器是否复用了这些引脚）。
    2. 检查**供电系统**。在调试中我们发现杜邦线无法承受大电流，甚至出现了**接上电源线直接烧毁（发热熔化）**的极端情况。这极大可能是因为供电线径太细、接线端子接触不良，或者电路存在瞬间短路。
    3. 下一步计划将动力电源（电池直接接TB6612的VM）与控制电源（降压模块给STM32供电）彻底隔离走线，加粗电源线，确保在电机启动瞬间主控芯片不会因为电压拉低而复位死机。

## 3. 技术选型与设计思路（为什么这样做）

*   **PS2遥控协议**：相比蓝牙或WiFi，PS2手柄的2.4G通信延迟极低，实时操控手感好，且抗干扰能力强，非常适合比赛现场复杂的电磁环境。
*   **PWM调速频率**：在CubeMX中，我们将定时器PWM频率配置为10kHz。这个频率既超出了人耳听觉范围（避免电机发出刺耳啸叫），又能保证电机在低速运转时有足够的平滑度。
*   **电机死区控制**：在电机换向代码中加入了1ms的死区延时，防止TB6612的H桥上下管同时导通导致短路烧毁。

## 4. 后续优化方向
1. 彻底解决电源供电烧线的问题，重新规划PCB或使用更粗的硅胶线连接大电流通路。
2. 完成摇杆模拟值到电机速度（-100~100）的线性映射，加入死区阈值防手抖漂移。
3. 实现麦克纳姆轮的全向移动解算（Vx, Vy, Vw）与遥控器的联动。
